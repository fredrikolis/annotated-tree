Strict-check report — `--strict-check --format json` and MCP `strict_check`

{
  "passed":         bool,          // true iff no annotation violations AND no rule violations
  "error_count":    integer,       // number of annotation violations
  "files_checked":  integer,       // code files examined
  "annotated_count":integer,       // how many of files_checked already carry a conforming annotation (convergence numerator)
  "violations":     [ Violation, … ],
  "orphan_sidecars":[ OrphanSidecar, … ],
  "rule_violations":[ RuleViolation, … ]
}

Violation = {
  "path":       string,            // path relative to the checked root (unix slashes)
  "line":       integer,           // 1-based line the scan landed on (past shebang/blanks)
  "language":   string,            // resolved language name
  "category":   "missing_annotation" | "malformed_annotation" | "annotation_too_long",
  "marker":     string,            // the comment delimiter this language expects
  "example":    string,            // a canonical self-conforming line for this language (a guaranteed-valid concrete instance)
  "defect":     {                  // machine-coded delta — the template parts at fault (branch on THIS, not message)
    "missing":  [ "concern" | "non_concern" | "io", … ],   // absent OR empty — all three if a broken ` | ` structure yields no part;  key omitted when the list is empty
    "too_long": [ { "part": "concern" | "non_concern" | "io", "length": integer }, … ],  // over-length fields, length in characters;  key omitted when the list is empty
    "max":      integer            // the per-part bound the too_long fields breached, once per violation;  key omitted when none applies
  },
  "expected":   {                  // the canonical contract to converge on (identical on every violation)
    "template":    string,         // "Concern: {what it does} | Non-concern: {what it isn't} | IO: (in) -> out  OR  none"
    "required":    [ string, … ],  // fields that FAIL the check when absent, empty, or over the bound (concern, non_concern, io)
    "recommended": [ string, … ]   // advised-only fields (empty: all three are required)
  },
  "found":      string | null,     // the offending line (raw for missing / actual for malformed/too long), null if none
  "suggestion": string,            // a FILE-TAILORED candidate: reused text + `<…>` placeholder slots; well formed as printed;  key omitted for annotation_too_long
  "detail":     string             // human prose where the machine fields alone would mislead (e.g. a present-but-empty field);  absent when they suffice
}

OrphanSidecar = {
  "path":     string,              // the <name>.annotation sidecar, relative to the root (unix slashes)
  "target":   string,              // the sibling file it names, which does not exist
  "message":  string               // human detail (the TEXT report emits "path: message")
}

RuleViolation = {
  "code":     "denied_dependency" | "dependency_cycle" | "orphan_package" | "unknown_deny_package" | "missing_package_charter",
  "message":  string,              // the architectural `[rules]` finding, human-readable (dual-render)
  "packages": [ string, … ],       // participating package name(s); the ordered node path for a cycle
  "path":     string               // offending package dir, relative to the root (unix slashes); absent when none applies
}

An agent dispatches on `category`/`code` (stable) and the structured fields, never on
`message`/`detail` prose. On a violation, `defect` is the machine delta (which of the three
fields are absent or empty, and which are over the length bound), `expected` is the contract to
converge on, and `suggestion` is a file-tailored stub whose judgment slots are left as `<…>`
placeholders. That stub is well formed, so applying it clears the form defect instead of
trading it for a second one. It is not a finished annotation: each `<…>` slot is a judgment an
agent still has to write out, and a configured length bound applies to the stub like any other
line. No `suggestion` is emitted for `annotation_too_long`, whose remedy is to shorten the
field. `annotated_count` of `files_checked` is the progress toward full coverage (the TEXT
footer prints "N of M files annotated"). Three violation categories FAIL the check and set a
nonzero exit: `missing_annotation` (no conforming comment), `malformed_annotation` (a comment
that is not the three-field `Concern: … | Non-concern: … | IO: …` shape, or one of whose fields
is empty after trimming), and `annotation_too_long` (a field longer than the `[rules]
max_annotation_length` / `--max-length` bound, which SHIPS AT 200 and is turned off with
`--max-length 0` — measured in characters over each field's MAXIMAL span: `Concern` up to the
LAST ` | Non-concern:`, `Non-concern` from the first of those to the LAST ` | IO:`, `IO` from
the first of those to the end of the line. On a conforming line each separator occurs once, so a
span is exactly the trimmed field value; an annotation whose prose QUOTES a separator
over-measures and fails loudly rather than under-measuring. A field exactly at the bound
passes). What a field SAYS is never a finding: the check is form only. A bare, marker-less `.annotation`
line is enforced by the SAME grammar at both scales and, when malformed or over-length, appears
as a Violation located at the `.annotation` file that HOLDS it: a directory's charter breadcrumb
with `language: "charter"` and `path: "<dir>/.annotation"`, and a file's sidecar with
`language: "sidecar"` and `path: "<dir>/<name>.annotation"`. A sidecar carries the contract of a
file that maps to no comment marker (a CSV, a dataset) and listing it is that file's opt-in; one
whose named file does not exist annotates nothing and is reported in `orphan_sidecars` — a
dangling PATH, not an issue about an Annotation — which also FAILS the check.
The opt-in `[rules] require_package_charter` gate adds a `missing_package_charter`
RuleViolation for a manifest-bearing package that owns annotated files yet resolves no charter
(off by default). `path` on a RuleViolation is absent (not null) when no single directory
applies — a cycle spanning many packages, or a deny rule naming an absent package.
