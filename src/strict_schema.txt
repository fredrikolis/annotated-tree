Strict-check report — `--strict-check --format json`

{
  "passed":         bool,          // true iff no annotation violations AND no rule violations
  "error_count":    integer,       // number of annotation violations
  "files_checked":  integer,       // code files examined
  "annotated_count":integer,       // how many of files_checked already carry a conforming annotation (convergence numerator)
  "violations":     [ Violation, … ],
  "orphan_sidecars":[ OrphanSidecar, … ],
  "rule_violations":[ RuleViolation, … ]
}

Violation = {
  "path":       string,            // path relative to the checked root (unix slashes)
  "line":       integer,           // 1-based line the scan landed on (past shebang/blanks)
  "language":   string,            // resolved language name
  "category":   "missing_annotation" | "malformed_annotation" | "annotation_too_long",
  "marker":     string,            // the comment delimiter this language expects
  "example":    string,            // a canonical self-conforming line for this language (a guaranteed-valid concrete instance)
  "defect":     {                  // machine-coded delta — the template parts at fault (branch on THIS, not message)
    "missing":  [ "concern" | "non_concern" | "io", … ],   // absent OR empty — all three if a broken ` | ` structure yields no part;  key omitted when the list is empty
    "length":   integer            // the annotation's length in characters, when it breached the bound;  key omitted when none applies
    "max":      integer            // the bound it breached, once per violation;  key omitted when none applies
  },
  "expected":   {                  // the canonical contract to converge on (identical on every violation)
    "template":    string,         // "Concern: {what it does} | Non-concern: {what it isn't} | IO: (in) -> out  OR  none"
    "required":    [ string, … ],  // fields that FAIL the check when absent, empty, or over the bound (concern, non_concern, io)
    "recommended": [ string, … ]   // advised-only fields (empty: all three are required)
  },
  "found":      string | null,     // the offending line (raw for missing / actual for malformed/too long), null if none
  "suggestion": string,            // a FILE-TAILORED candidate: reused text + `<…>` placeholder slots; well formed as printed;  key omitted for annotation_too_long
  "detail":     string             // human prose where the machine fields alone would mislead (e.g. a present-but-empty field);  absent when they suffice
}

OrphanSidecar = {
  "path":     string,              // the <name>.annotation sidecar, relative to the root (unix slashes)
  "target":   string,              // the sibling file it names, which does not exist
  "message":  string               // human detail (the TEXT report emits "path: message")
}

RuleViolation = {
  "code":     "denied_dependency" | "dependency_cycle" | "orphan_package" | "unknown_deny_package" | "missing_package_charter",
  "message":  string,              // the architectural `[rules]` finding, human-readable (dual-render)
  "packages": [ string, … ],       // participating package name(s); the ordered node path for a cycle
  "path":     string               // offending package dir, relative to the root (unix slashes); absent when none applies
}

Dispatch on `category` / `code` and the structured fields. Never parse `message` / `detail`.

Every category below FAILS the check and sets a nonzero exit. The check is form only: what a
field SAYS is never a finding.

  missing_annotation    no conforming comment on the landing line
  malformed_annotation  not the three-field `Concern: … | Non-concern: … | IO: …` shape, or a
                        field empty after trimming
  annotation_too_long   longer than the `[rules] max_annotation_length` / `--max-length` bound,
                        counted over the WHOLE annotation rather than any one field; a line
                        exactly at the bound passes

Per violation:

  defect      the machine delta — which fields are absent or empty, plus `length` vs `max`
  expected    the contract to converge on; identical on every violation
  suggestion  a file-tailored stub, well formed as printed, so applying it clears the form
              defect rather than trading it for a second one. Not a finished annotation: each
              `<…>` slot is a judgment to write out, and the length bound applies to the stub
              like any other line. Omitted for `annotation_too_long` — shorten the line instead.

`annotated_count` of `files_checked` is coverage progress (the TEXT footer prints "N of M
files annotated").

Bare, marker-less `.annotation` bodies are enforced by the SAME grammar at both scales and
reported as a Violation located at the file that HOLDS the line: a directory charter as
`language: "charter"`, `path: "<dir>/.annotation"`; a file sidecar as `language: "sidecar"`,
`path: "<dir>/<name>.annotation"`. A sidecar carries the contract of a file that maps to no
comment marker (a CSV, a dataset), and writing it is that file's opt-in. A sidecar naming a
file that does not exist lands in `orphan_sidecars` — a dangling PATH, not an issue about an
Annotation — and also FAILS the check.

`missing_package_charter` fires only under the opt-in `[rules] require_package_charter`: a
manifest-bearing package that owns annotated files yet resolves no charter. A RuleViolation's
`path` is absent (not null) when no single directory applies — a cycle spanning many packages,
or a deny rule naming an absent package.
